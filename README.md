# Drone Race：用 RL 學「穿過房間飛到目標 + 自動避障」

用 [Genesis](https://github.com/Genesis-Embodied-AI/genesis-world) 模擬器同時跑上千架 Crazyflie（cf2x），再用 [rsl-rl](https://github.com/leggedrobotics/rsl_rl) 的 PPO 訓練。
目前這個階段，AI 直接知道障礙物的位置。架構上已經把「任務邏輯」和「模擬器」分開，之後要換成 Isaac Lab 或深度相機，都不用重寫任務。

## 安裝

```bash
uv venv .venv --python 3.12                      # 或 conda create -n drone python=3.12
uv pip install --python .venv/Scripts/python.exe torch==2.15.0 --index-url https://download.pytorch.org/whl/cu132
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
```

RTX 50 系列（Blackwell）需要 CUDA 12.8 以上的 torch build；Windows 上 torch 2.15.0 只有 cu132 / cu134 版本。

## 使用

```bash
python check_env.py                                  # 環境自我檢查（見下方「檢查項目」）
python plot_layouts.py --level 4 --num 12            # 畫出隨機房間佈局的俯視圖 -> logs/layouts_level4.png
python train.py --num_envs 4096 --max_iterations 6000 --exp_name rooms   # 訓練，結果存到 logs/rooms/<時間>/
python train.py --resume logs/rooms/<時間>/model_5999.pt --level 4        # 從某個 checkpoint、某個等級繼續訓練
tensorboard --logdir logs                            # 看成功率、碰撞率、路線完成度、平均速度、curriculum 等級
python eval.py --run logs/rooms/<時間>                # 用最難的等級評估
python eval.py --run logs/rooms/<時間> --plot 12      # 另外畫 12 個 episode 的俯視軌跡圖
python eval.py --run logs/rooms/<時間> --level 2 --record   # 另外錄一段 env 0 的 mp4（高空俯視追蹤）
python eval.py --run logs/rooms/<時間> --rooms 6 6 --partitions 2 2 --pillars 5 5   # 測試特定條件
python eval.py --run logs/rooms/<時間> --viewer --num_envs 1
```

多 GPU 的電腦（例如 2 張 5080）：用 `CUDA_VISIBLE_DEVICES=0` 或 `CUDA_VISIBLE_DEVICES=1` 指定 GPU，一張卡跑一組實驗；也可以把 `--num_envs` 開大。

## 任務設計

| 項目 | 內容 |
|---|---|
| 場景 | 每個 episode 隨機產生一串矩形房間（邊長 4–8 m）。每個房間接在前一個房間「入口以外」的任一面，兩房間共用的牆上只開一個門，位置和寬度都隨機；其他牆全部封死，所以從起點到終點只有一條路。起點靠著第一個房間的某面牆，終點靠著最後一個房間的某面牆（見 [task/rooms.py](task/rooms.py)） |
| 房內障礙 | **隔間牆**：橫跨整個房間、只留一個缺口，連續兩道的缺口有 70% 機率在不同側，逼出 S 形路線。**獨立短牆**：0.8–2 m、任意角度。**圓柱**：半徑 0.1–0.3 m。短牆和柱子 80% 沿著直線路線附近放，確保真的擋路。牆和柱子都比天花板高，只能繞，不能從上面飛過 |
| 一定過得去 | 由產生規則保證：隔間牆彼此平行、缺口至少一個門寬；每根柱子和每段短牆跟其他任何東西至少保持 0.5 m 間隙，所以不可能把通道封死。門、缺口、起點、終點周圍 1 m 內不放障礙。`check_env.py` 會用格點 flood fill 驗證 |
| 動作（4 維，範圍 [-1, 1]） | **CTBR**：總推力（0 = 懸停推力）+ 三軸角速度指令。由 [control/ctbr.py](control/ctbr.py) 的角速度控制器和 mixer 換算成四顆馬達的推力。Crazyflie、PX4、Betaflight 都吃這個介面 |
| 觀測（180 維，都在機體座標系） | 線速度、角速度、重力方向、上一步的動作、高度；**目前房間的出口**（門的方向、距離、穿越方向、門寬；最後一間就是終點）和下一個房間的出口；最近 8 根柱子的相對位置和表面距離；最近 12 段牆：最近點、以及牆在感測範圍（6 m）內那一段的兩個端點、距離。AI 只知道門在哪，房內隔間牆的缺口要自己從牆的端點看出來 |
| Critic 額外觀測（6 維） | 下一個路線點（可能是隔間缺口）、沿路線剩下的距離、已用掉的時間比例。只給 critic，訓練完的 policy 用不到 |
| 獎勵 | **沿路線**前進的距離 × 5（路線 = 依序經過隔間缺口和門的折線，所以不會叫 AI 往牆上推；用 potential 差值，來回穿門不會賺分）、每一步扣 0.01、**超過 3 m/s 的速度懲罰**、**朝柱子 / 獨立短牆的接近速度懲罰**（1 m 內，朝它靠近的速度分量 × 越近越重；從 1 m 外直直撞上去總共約 −12.5，擦身而過幾乎不扣）、角速度和動作變化的懲罰、yaw 旋轉的懲罰、輸出超出 [-1, 1] 的懲罰、離柱子或牆太近的懲罰、撞到 −40、到達 +10 |
| 速度要求 | 不追求最快，只要求平均速度 ≥ 1 m/s：每個 episode 的時間上限 = 5 s + 路線長度 ÷ 1 m/s，超過就算失敗。開闊處最划算的速度約 3.3 m/s |
| 結束條件 | 到達（距離 < 0.4 m）、撞到柱子、撞牆、撞地面或飛出天花板、跑出房間、超過時間上限 |
| Curriculum | 5 個等級，房間數 / 每間的隔間牆、短牆、柱子數量都是範圍：第 0 級 1–2 間、0 隔間、0 短牆、0–1 根柱子、門寬 1.2–1.6 m；最高到 1–6 間、0–2 隔間、0–2 短牆、0–5 根柱子、門寬 0.8–1.6 m。範圍只放寬、不平移，簡單的情況一直都在訓練裡。成功率 ≥ 80% 就升級 |
| 佈局池 | 佈局用 Python 產生（每個約 0.4 ms），一次產生 8192 個放在 GPU 上；reset 時直接抽，升級或平均每個佈局被抽 8 次之後重新產生 |
| 頻率 | 物理和角速度控制 100 Hz，策略 50 Hz |

所有參數都在 [config/task_cfg.py](config/task_cfg.py)。

### 檢查項目（`check_env.py`）

1. 隨機動作下觀測和獎勵的 shape 正確、沒有 NaN
2. 零動作懸停 2 秒不漂移；三軸角速度指令方向正確
3. 柱子放在無人機上 → 判定撞柱子；牆在 8 cm 外 → 判定撞牆；跑出所有房間 → 判定出界
4. 最難等級的 200 個佈局：房間不重疊；用格點 flood fill 確認起點到終點過得去（無人機半徑再加 2 cm 餘量）；**封住任何一扇門就到不了終點**（確認只有一條路）；路線記帳在終點剩 0、在起點等於整條路線長

## 訓練結果

### 第一版：開放場地（沒有圍牆，2026-10-29，RTX 3050 Ti）

AI 主要是從柱群外側繞過去，沒有真正學會在柱子之間閃避，所以後來加上了圍牆。
4096 個環境、2000 iterations。混合條件（0–8 根，2–12 m）成功率 98.0%、撞到 1.9%、平均 5.8 m/s。

### 第二版：封閉走廊（2026-10-29，RTX 3050 Ti）

4096 個環境、3000 iterations。加了圍牆以後 AI 確實得在柱子之間閃避，但柱子一密成功率就明顯下降：8 根、6–12 m 只有 39.8%，撞柱子 52.8%。撞擊瞬間的前進速度中位數約 10 m/s，大多是正面撞上，也就是 AI 還沒學會遇到密集區要先減速。這也是第三版改成「速度只要達標」的原因。

| 條件 | 成功率 | 撞柱子 | 撞牆 | 平均到達時間 | 平均速度 |
|---|---|---|---|---|---|
| 0 根，2–4 m | 99.5% | 0% | 0.5% | 0.66 s | 4.5 m/s |
| 4 根，4–8 m | 77.3% | 22.3% | 0.4% | 1.11 s | 5.4 m/s |
| 8 根，6–12 m | 39.8% | 52.8% | 6.3% | 1.50 s | 5.8 m/s |
| 混合（0–8 根，2–12 m） | 79.7% | 18.6% | 1.6% | 1.05 s | 6.0 m/s |

### 第三版：隨機房間（目前的版本）

訓練設定：4096 個環境、6000 iterations，總共約 5.9 億步。在 RTX 5080 上約 40 分鐘（每秒約 26 萬步）。Run 名稱是 `logs/rooms/2026-10-29_15-08-34`。Curriculum 在第 51 / 454 / 803 / 1538 iteration 升到第 1 / 2 / 3 / 4 級。
評估：用 deterministic policy，每種條件約 2000 個 episode。速度是「路線長度 ÷ 飛行時間」。

| 條件 | 成功率 | 撞柱子 | 撞牆 | 逾時 | 平均房間數 | 平均到達時間 | 平均速度 |
|---|---|---|---|---|---|---|---|
| 第 0 級（1–2 間、0–1 根柱子 / 間） | 99.5% | 0.2% | 0.3% | 0% | 1.4 | 2.3 s | 2.5 m/s |
| 第 1 級（1–3 間、0–1 隔間、0–1 短牆、0–2 柱子） | 96.5% | 1.3% | 2.1% | 0% | 1.9 | 3.8 s | 2.3 m/s |
| 第 2 級（1–4 間、0–1 隔間、0–1 短牆、0–3 柱子） | 95.8% | 2.0% | 2.3% | 0% | 2.2 | 4.9 s | 2.3 m/s |
| 第 3 級（1–5 間、0–2 隔間、0–2 短牆、0–4 柱子） | 93.3% | 2.9% | 3.7% | 0% | 2.6 | 6.3 s | 2.2 m/s |
| **第 4 級（1–6 間、0–2 隔間、0–2 短牆、0–5 柱子）** | **89.0%** | 5.8% | 5.2% | 0% | 3.1 | 7.7 s | 2.1 m/s |
| 全部拉滿（6 間，每間 2 隔間 + 2 短牆 + 5 柱子） | 67.4% | 15.0% | 17.0% | 0.1% | 6 | 21.1 s | 1.9 m/s |

「全部拉滿」時，小房間放不下的障礙會少放，所以實際平均是：穿過 5 扇門和 9.4 道隔間牆，繞過 7.9 段短牆和 17 根柱子，路線長約 40 m。路線平均完成 81%，換算下來每個房間的通過率約 94%。

單一障礙的拆解測試（第 4 級的門寬，只有 1 間房，另外只放指定的東西）：

| 情境 | 空房 | 1 根柱子 | 2 根柱子 | 1 段短牆 | 1 道隔間牆 | 3 間空房 |
|---|---|---|---|---|---|---|
| 成功率 | 99.7% | 99.4% | 97.9% | 98.4% | 98.7% | 99.9% |

**接近速度懲罰的效果**：同樣設定、只差這一項時，牆、門、隔間都學得很好，柱子卻學不會。空房間裡只放 1 根柱子就有 12% 撞上，訓練到第 2500 iteration 都還停在第 2 級。看軌跡會發現 AI 先往旁邊閃，接著又被終點方向拉回來，正對柱子中心撞上去。原因是進度獎勵沿路線計算，而路線會繞過牆、卻直接穿過柱子，所以在撞上之前完全沒有警告。加了這一項之後：1 根柱子的成功率從 87.5% 升到 99.4%；「起點和終點連線上放一根柱子」的 9 種位置，最差的情況從 79% 升到 100%；升到第 2 級的時間也從第 1937 iteration 提早到第 454 iteration。

剩下的失敗主要有兩種：
- 柱子或短牆跟隔間牆靠得很近，閃開一邊時撞上另一邊。
- 門或終點就在隔間牆正後方，但缺口在反方向時，偶爾會在牆前猶豫直到逾時（約 0.4%）。AI 沒有記憶，也看不到隔間缺口的路線點，所以「先遠離目標再繞回來」對它來說很難。

注意：Genesis 的無人機模型沒有空氣阻力，馬達反應也是瞬間的，所以速度會比真的 Crazyflie 樂觀。如果要上實機，要先加這兩項（見下方「之後的方向」）。

## 架構

```
train.py / eval.py ── rsl-rl PPO
        │
task/goal_nav_task.py (VecEnv) ── rooms（佈局產生 + GPU 佈局池）/ route / geometry / observations / rewards、control/ctbr.py   ← 純 torch，跟模擬器無關
        │  SimBackend 介面（backends/base.py）
backends/genesis_backend.py   ← 唯一會 import genesis 的檔案
```

- 無人機的物理參數集中在 [config/drone_params.py](config/drone_params.py)，所有後端都共用這一份。
- 碰撞（柱子和牆）和障礙物觀測都用 torch 解析計算，不靠模擬器的接觸偵測，所以換模擬器後判定結果完全一樣。牆是有厚度的線段，長度每個 episode 都不同。
- 因為碰撞是解析的，訓練時模擬器裡完全不放障礙物；只有開 viewer 或錄影時才建立用來顯示的柱子和牆。Genesis 建好場景後不能改方塊大小，所以任意長度的牆是用 2 m / 0.5 m 的方塊重疊拼出來的，而且只更新被畫出來的那個 env。

### 移植到 Isaac Lab

1. 新增 `backends/isaaclab_backend.py`，實作 `SimBackend` 的方法（座標慣例寫在 [backends/base.py](backends/base.py) 開頭的說明裡）。`apply_rotor_thrusts` 可以把每顆馬達的推力換算成力和力矩，再用 `set_external_force_and_torque` 套用。
2. 在 `make_backend()` 註冊 `"isaaclab"`。
3. 執行 `python check_env.py --backend isaaclab`，確認懸停、角速度方向和碰撞判定都和 Genesis 一致。
4. 執行 `python train.py --backend isaaclab`。任務、獎勵、控制器和 PPO 設定都不用改。

## 之後的方向

- **換成深度相機**：實作 `SimBackend.get_depth()`（Genesis 用 BatchRenderer，Isaac Lab 用 TiledCamera），把 `obs.mode` 設成 `"depth"`，然後在 `GoalNavTask._compute_obs` 用影像取代柱子和牆那兩段觀測。因為場景全是垂直的牆和圓柱，也可以直接在 torch 裡對線段和圓做 ray casting，產生類似光達的距離觀測，不用模擬器渲染。可以用 rsl-rl 的 distillation，讓這一階段的策略當老師。
- **繼續訓練**：第 4 級的成功率到第 6000 iteration 都還在緩慢上升，可以用 `--resume ... --level 4` 接著練。
- **處理「目標在牆後」的局部極小值**：換成有記憶的 policy（rsl-rl 支援 RNN），或是讓 policy 也看到房內的下一個路線點（目前只給 critic）。前者比較接近「真正學會找路」。
- **提高速度**：目前速度只要求達標。避障穩定以後，可以把 `rewards.max_speed` 往上調、或把 `time` 懲罰加大，再接著訓練。
- **上實機**：實作 `domain_rand`（質量、推力、延遲），加入空氣阻力和馬達動態，再用 `runner.export_policy_to_onnx` 匯出策略。
