# Drone Race：用 RL 學「穿過房間飛到目標 + 3D 避障」

用 [Genesis](https://github.com/Genesis-Embodied-AI/genesis-world) 模擬器同時跑上千架 Crazyflie（cf2x），再用 [rsl-rl](https://github.com/leggedrobotics/rsl_rl) 的 PPO 訓練。
目前這個階段，AI 直接知道障礙物的位置。架構上已經把「任務邏輯」和「模擬器」分開，之後要換成 Isaac Lab 或深度相機，都不用重寫任務。

## 安裝

```bash
uv venv .venv --python 3.12                      # 或 conda create -n drone python=3.12
uv pip install --python .venv/Scripts/python.exe torch==2.15.0 --index-url https://download.pytorch.org/whl/cu132
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
```

RTX 50 系列（Blackwell）需要 CUDA 12.8 以上的 torch build；Windows 上 torch 2.15.0 只有 cu132 / cu134 版本。

## 使用

```bash
python check_env.py                                  # 環境自我檢查（見下方「檢查項目」）
python plot_layouts.py --level 4 --num 12            # 畫出隨機房間佈局的俯視圖 -> logs/layouts_level4.png
python train.py --num_envs 4096 --max_iterations 8000 --exp_name rooms3d # 訓練，結果存到 logs/rooms3d/<時間>/
python train.py --resume logs/rooms3d/<時間>/model_7999.pt --level 5      # 從某個 checkpoint、某個等級繼續訓練
python train.py ... --set rewards.approach_wall=0 rewards.slow_clearance=0      # 覆寫設定值（例如做對照實驗）
tensorboard --logdir logs                            # 看成功率、碰撞率、路線完成度、平均速度、curriculum 等級
python eval.py --run logs/rooms3d/<時間>              # 用最難的等級評估（每個環境只算前 K 個 episode，見下方說明）
python eval.py --run logs/rooms3d/<時間> --plot 12    # 另外畫 12 個 episode 的俯視軌跡圖（軌跡顏色 = 高度）
python eval.py --run logs/rooms3d/<時間> --level 2 --record   # 另外錄一段 env 0 的 mp4（高空望遠俯視；黃點是無人機，藍點是軌跡）
python record_fpv.py --run logs/rooms3d/<時間> --max --episodes 5    # 第一人稱視角錄影：每個 episode 一支，再加一支合輯（存在 <run>/videos/）
python eval.py --run logs/rooms3d/<時間> --rooms 6 6 --partitions 2 2 --pillars 5 5   # 測試特定條件
python eval.py --run logs/rooms3d/<時間> --vertical 1.0 --ceiling 2.5 2.5              # 門全是窗戶、天花板很低
python eval.py --run logs/rooms3d/<時間> --viewer --num_envs 1
```

多 GPU 的電腦（例如 2 張 5080）：用 `CUDA_VISIBLE_DEVICES=0` 或 `CUDA_VISIBLE_DEVICES=1` 指定 GPU，一張卡跑一組實驗；也可以把 `--num_envs` 開大。

## 任務設計

| 項目 | 內容 |
|---|---|
| 場景 | 每個 episode 隨機產生一串矩形房間（邊長 4–8 m，**每間天花板高度不同**）。每個房間接在前一個房間「入口以外」的任一面，兩房間共用的牆上只開一個門，位置和寬度都隨機；其他牆全部封死，所以從起點到終點只有一條路。**門可能是窗戶**：開口離地 0.3 m 以上、高 0.8–1.4 m，要爬升或下降才過得去。起點和終點的高度也隨機（見 [task/rooms.py](task/rooms.py)） |
| 房內障礙 | **隔間牆**橫跨整個房間，只能從它的開口過：缺口（連續兩道的缺口有 70% 機率在不同側，逼出 S 形路線）、窗戶、**矮牆**（從上面飛過）、**吊牆**（從下面鑽過）。**獨立短牆**：0.8–2 m、任意角度，可能是全高、矮牆、吊牆或半空中的**橫樑**。**圓柱**：半徑 0.1–0.3 m，可能是全高、**矮柱**或**吊柱**。短牆和柱子 80% 沿著直線路線附近放，確保真的擋路。全高的牆和柱子都比天花板高 |
| 3D 幾何 | 每個障礙物都是「2D 形狀（有厚度的線段或圓）× 一段高度 [z_low, z_high]」。到它的距離 = √(水平距離² + 高度方向超出量²)，是精確的解析解，所以碰撞判定和觀測都很快，也不依賴模擬器 |
| 一定過得去 | 由產生規則保證：隔間牆彼此平行，每個開口至少一個門寬寬、0.8 m 高；每根柱子和每段短牆跟其他任何東西在水平方向至少保持 0.5 m 間隙，所以不管它多高都封不死通道。門、開口、起點、終點周圍 1 m 內不放障礙。`check_env.py` 會用 3D 體素 flood fill 驗證 |
| 動作（4 維，範圍 [-1, 1]） | **CTBR**：總推力（0 = 懸停推力）+ 三軸角速度指令。由 [control/ctbr.py](control/ctbr.py) 的角速度控制器和 mixer 換算成四顆馬達的推力。Crazyflie、PX4、Betaflight 都吃這個介面 |
| 觀測（271 維，都在機體座標系） | 線速度、角速度、重力方向、上一步的動作、高度、離天花板的距離；**目前房間的出口**（門的方向、距離、穿越方向、門寬、開口的上下緣；最後一間就是終點）和下一個房間的出口；最近 8 根柱子：軸上最近點的相對位置、底和頂相對於無人機的高度、到表面的 3D 距離；最近 16 段牆：最近點、牆在感測範圍（6 m）內那一段的兩個端點、底和頂的相對高度、3D 距離。AI 只知道門在哪，房內隔間牆的開口要自己從牆的端點和上下緣看出來 |
| Critic 額外觀測（6 維） | 下一個路線點（可能是隔間的開口）、沿路線剩下的距離、已用掉的時間比例。只給 critic，訓練完的 policy 用不到 |
| 獎勵 | **沿 3D 路線**前進的距離 × 5（路線 = 依序經過隔間開口和門的折線；路線點的高度從終點往回推，夾進每個開口的高度範圍，所以直線一定穿過開口，不會叫 AI 往牆上推；用 potential 差值，來回穿門不會賺分）、每一步扣 0.01、**速度上限懲罰**（開闊處 3 m/s，離最近的牆或柱子 1 m 內線性降到 1.2 m/s）、**朝柱子 / 獨立短牆的接近速度懲罰**（1 m 內，朝它靠近的速度分量 × 越近越重；從 1 m 外直直撞上去總共約 −12.5，擦身而過幾乎不扣）、**朝房間牆 / 隔間牆的接近速度懲罰**（權重減半；垂直穿過開口中央幾乎不扣，斜著切過開口或高度沒對準會扣）、角速度和動作變化的懲罰、yaw 旋轉的懲罰、輸出超出 [-1, 1] 的懲罰、離柱子或牆太近的懲罰、撞到 −40、到達 +10 |
| 速度要求 | 不追求最快，只要求平均速度 ≥ 1 m/s：每個 episode 的時間上限 = 5 s + 路線長度 ÷ 1 m/s，超過就算失敗。開闊處最划算的速度約 3.3 m/s，靠近障礙會自動慢下來 |
| 結束條件 | 到達（距離 < 0.4 m）、撞到柱子、撞牆、撞地面、撞到所在房間的天花板、跑出房間、超過時間上限 |
| Curriculum | 5 個等級，房間數 / 每間的隔間牆、短牆、柱子數量都是範圍：第 0 級 1–2 間、0 隔間、0 短牆、0–1 根柱子、門寬 1.2–1.6 m、天花板 3.5 m、沒有高度變化（等於 2D）；最高到 1–6 間、0–2 隔間、0–2 短牆、0–5 根柱子、門寬 0.8–1.6 m、天花板 2.5–4 m，每扇門 / 每道隔間 / 每個障礙物有 50% 機率是窗戶、矮的、吊的或橫樑（`vertical`）。第 0–4 級的範圍只放寬、不平移，簡單的情況一直都在訓練裡。**第 5 級只放擁擠的房間**：3–6 間，每間 1–2 隔間、1–2 短牆、2–5 根柱子。另外每個等級都有 25% 的佈局從比較簡單的等級隨機抽（`replay`），避免忘記只有簡單佈局才練得到的技能，例如在空房間裡對終點煞車。成功率 ≥ 80% 就升級 |
| 佈局池 | 佈局用 Python 產生（每個約 0.4 ms），一次產生 8192 個放在 GPU 上；reset 時直接抽，升級或平均每個佈局被抽 8 次之後重新產生 |
| 頻率 | 物理和角速度控制 100 Hz，策略 50 Hz |

所有參數都在 [config/task_cfg.py](config/task_cfg.py)。

### 檢查項目（`check_env.py`）

1. 隨機動作下觀測和獎勵的 shape 正確、沒有 NaN
2. 零動作懸停 2 秒不漂移；三軸角速度指令方向正確
3. 柱子放在無人機上 → 判定撞柱子；牆在 8 cm 外 → 判定撞牆；同一面牆如果從無人機上方 15 cm 開始、或在下方 15 cm 結束 → **不算撞**，往下延伸到無人機的高度 → 算撞；碰到天花板、跑出所有房間 → 判定出界
4. 最難等級的 200 個佈局：房間不重疊；用 0.1 m 的 3D 體素 flood fill 確認起點到終點過得去（無人機半徑再加 2 cm 餘量）；**封住任何一扇門就到不了終點**（確認只有一條路）；路線記帳在終點剩 0、在起點等於整條路線長

## 訓練結果

### 第一版：開放場地（沒有圍牆，2026-10-29，RTX 3050 Ti）

AI 主要是從柱群外側繞過去，沒有真正學會在柱子之間閃避，所以後來加上了圍牆。
4096 個環境、2000 iterations。混合條件（0–8 根，2–12 m）成功率 98.0%、撞到 1.9%、平均 5.8 m/s。

### 第二版：封閉走廊（2026-10-29，RTX 3050 Ti）

4096 個環境、3000 iterations。加了圍牆以後 AI 確實得在柱子之間閃避，但柱子一密成功率就明顯下降：8 根、6–12 m 只有 39.8%，撞柱子 52.8%。撞擊瞬間的前進速度中位數約 10 m/s，大多是正面撞上，也就是 AI 還沒學會遇到密集區要先減速。這也是第三版改成「速度只要達標」的原因。

| 條件 | 成功率 | 撞柱子 | 撞牆 | 平均到達時間 | 平均速度 |
|---|---|---|---|---|---|
| 0 根，2–4 m | 99.5% | 0% | 0.5% | 0.66 s | 4.5 m/s |
| 4 根，4–8 m | 77.3% | 22.3% | 0.4% | 1.11 s | 5.4 m/s |
| 8 根，6–12 m | 39.8% | 52.8% | 6.3% | 1.50 s | 5.8 m/s |
| 混合（0–8 根，2–12 m） | 79.7% | 18.6% | 1.6% | 1.05 s | 6.0 m/s |

### 第三版：隨機房間（2D，牆和柱子都是全高）

訓練設定：4096 個環境、6000 iterations，總共約 5.9 億步。在 RTX 5080 上約 40 分鐘（每秒約 26 萬步）。Run 名稱是 `logs/rooms/2026-10-29_15-08-34`。Curriculum 在第 51 / 454 / 803 / 1538 iteration 升到第 1 / 2 / 3 / 4 級。
評估：用 deterministic policy，每種條件約 2000 個 episode。速度是「路線長度 ÷ 飛行時間」。

| 條件 | 成功率 | 撞柱子 | 撞牆 | 逾時 | 平均房間數 | 平均到達時間 | 平均速度 |
|---|---|---|---|---|---|---|---|
| 第 0 級（1–2 間、0–1 根柱子 / 間） | 99.5% | 0.2% | 0.3% | 0% | 1.4 | 2.3 s | 2.5 m/s |
| 第 1 級（1–3 間、0–1 隔間、0–1 短牆、0–2 柱子） | 96.5% | 1.3% | 2.1% | 0% | 1.9 | 3.8 s | 2.3 m/s |
| 第 2 級（1–4 間、0–1 隔間、0–1 短牆、0–3 柱子） | 95.8% | 2.0% | 2.3% | 0% | 2.2 | 4.9 s | 2.3 m/s |
| 第 3 級（1–5 間、0–2 隔間、0–2 短牆、0–4 柱子） | 93.3% | 2.9% | 3.7% | 0% | 2.6 | 6.3 s | 2.2 m/s |
| **第 4 級（1–6 間、0–2 隔間、0–2 短牆、0–5 柱子）** | **89.0%** | 5.8% | 5.2% | 0% | 3.1 | 7.7 s | 2.1 m/s |
| 全部拉滿（6 間，每間 2 隔間 + 2 短牆 + 5 柱子） | 67.4% | 15.0% | 17.0% | 0.1% | 6 | 21.1 s | 1.9 m/s |

「全部拉滿」時，小房間放不下的障礙會少放，所以實際平均是：穿過 5 扇門和 9.4 道隔間牆，繞過 7.9 段短牆和 17 根柱子，路線長約 40 m。路線平均完成 81%，換算下來每個房間的通過率約 94%。

單一障礙的拆解測試（第 4 級的門寬，只有 1 間房，另外只放指定的東西）：

| 情境 | 空房 | 1 根柱子 | 2 根柱子 | 1 段短牆 | 1 道隔間牆 | 3 間空房 |
|---|---|---|---|---|---|---|
| 成功率 | 99.7% | 99.4% | 97.9% | 98.4% | 98.7% | 99.9% |

**接近速度懲罰的效果**：同樣設定、只差這一項時，牆、門、隔間都學得很好，柱子卻學不會。空房間裡只放 1 根柱子就有 12% 撞上，訓練到第 2500 iteration 都還停在第 2 級。看軌跡會發現 AI 先往旁邊閃，接著又被終點方向拉回來，正對柱子中心撞上去。原因是進度獎勵沿路線計算，而路線會繞過牆、卻直接穿過柱子，所以在撞上之前完全沒有警告。加了這一項之後：1 根柱子的成功率從 87.5% 升到 99.4%；「起點和終點連線上放一根柱子」的 9 種位置，最差的情況從 79% 升到 100%；升到第 2 級的時間也從第 1937 iteration 提早到第 454 iteration。

剩下的失敗主要有兩種：
- 柱子或短牆跟隔間牆靠得很近，閃開一邊時撞上另一邊。
- 門或終點就在隔間牆正後方，但缺口在反方向時，偶爾會在牆前猶豫直到逾時（約 0.4%）。AI 沒有記憶，也看不到隔間缺口的路線點，所以「先遠離目標再繞回來」對它來說很難。

### 第四版：3D 隨機房間

訓練設定：4096 個環境、8000 iterations，總共約 7.9 億步。在 RTX 5080 上約 55 分鐘。Run 名稱是 `logs/rooms3d/2026-10-29_16-22-05`。Curriculum 在第 56 / 835 / 1682 / 3076 iteration 升到第 1 / 2 / 3 / 4 級。

| 條件 | 成功率 | 撞柱子 | 撞牆 | 出界 | 逾時 | 平均到達時間 | 平均速度 |
|---|---|---|---|---|---|---|---|
| 第 0 級（等於 2D） | 99.8% | 0.1% | 0.1% | 0% | 0% | 2.5 s | 2.6 m/s |
| 第 1 級（25% 有高度變化，天花板 3–3.5 m） | 96.7% | 0.9% | 2.1% | 0.1% | 0.1% | 4.3 s | 2.4 m/s |
| 第 2 級（40%，2.75–3.75 m） | 96.9% | 2.0% | 1.1% | 0% | 0% | 5.5 s | 2.4 m/s |
| 第 3 級（50%，2.5–4 m） | 91.5% | 3.9% | 4.2% | 0.1% | 0.3% | 7.2 s | 2.3 m/s |
| **第 4 級（50%，2.5–4 m，1–6 間）** | **87.7%** | 5.6% | 6.0% | 0.3% | 0.4% | 8.4 s | 2.2 m/s |
| 第 4 級，全部都有高度變化（`--vertical 1.0`） | 90.1% | 2.5% | 6.7% | 0.5% | 0.1% | 7.5 s | 2.4 m/s |
| 第 4 級，完全平面（`--vertical 0 --ceiling 3.5 3.5`） | 83.3% | 10.3% | 5.8% | 0.1% | 0.5% | 9.9 s | 2.0 m/s |
| 全部拉滿（6 間，每間 2 隔間 + 2 短牆 + 5 柱子） | 69.8% | 12.0% | 15.4% | 0.9% | 1.8% | 19.7 s | 2.0 m/s |

「出界」在這一版包含撞到所在房間的天花板。

單一 3D 情境的拆解測試（只有指定的東西；「高度變化」= `vertical 1.0`）：

| 情境 | 成功率 |
|---|---|
| 1 間空房 | 100% |
| 2 根全高柱子 / 2 根矮柱或吊柱 | 98.4% / 99.7% |
| 1 段全高短牆 / 1 段矮牆、吊牆或橫樑 | 99.5% / 99.8% |
| 1 道缺口隔間 / 1 道窗戶、矮牆或吊牆隔間 | 98.9% / 99.2% |
| 3 間房，門是一般門 / 全是窗戶 / 全是窗戶且天花板只有 2.5 m | 99.9% / 100% / 99.9% |

從俯視軌跡圖可以看到明確的 3D 行為：遇到矮牆會爬升到牆頂之上，遇到吊牆和橫樑會壓低到 0.6–0.8 m 從下面鑽過，穿過窗戶前會先調整到窗戶的高度。

全部拉滿只有 69.8%。失敗分析（每個 episode 在重置前記下撞到的物體）顯示：
- 每間房的失敗率 5–7%，6 間累積下來就剩七成。
- 失敗有 69% 是撞上全高障礙：全高柱子 35%、隔間缺口邊緣 20%、全高短牆 7%。
- 房內全高柱子越多，失敗率升得越快：0 根 3.2%，5 根 18.6%。但這種密度在第 4 級的訓練中很少出現。
- 撞擊時的速度中位數是 2.6 m/s，比成功時的平均 2.0 m/s 還快，代表在擁擠處沒有減速。

這些發現就是第五版改動的依據。

### 第五版：擁擠課程 + 擁擠處減速 + 牆的接近懲罰 + 複習（目前的版本）

從第四版的 model_7999 接著訓練，加入四項改動：
1. **第 5 級**：只放擁擠的房間。
2. **擁擠處減速**：速度上限在離牆或柱子 1 m 內線性降到 1.2 m/s。
3. **房間牆 / 隔間的接近懲罰**：權重是柱子的一半。
4. **複習**：25% 的佈局從比較簡單的等級抽。

前三項一起訓練 4000 iterations（28 分鐘），再加第 4 項訓練 2000 iterations（14 分鐘）。為了分開各項的效果，另外跑了一組「只換課程」的對照（4000 iterations，獎勵不變）。最終模型是 `logs/rooms3d_ft_replay/2026-10-29_18-40-18/model_13997.pt`。

| 條件 | 第四版 | 只換課程 | 三項全做 | **最終（+ 複習）** | 最終：撞柱 / 撞牆 / 逾時 | 平均速度 |
|---|---|---|---|---|---|---|
| 第 0 級 | 99.8% | 98.1% | 95.4% | **99.6%** | 0.3% / 0% / 0% | 2.6 → 2.2 m/s |

- **每項改動都有用，減速和牆的接近懲罰貢獻最大。**全部拉滿的成功率：只換課程 +7.8 個百分點；加上減速和牆的接近懲罰，再 +14.9；加上複習，再 +2.5。
- **複習是必要的。**第 5 級拿掉了單間、空房間的佈局後，「三項全做」在第 0 級從 99.8% 掉到 95.4%：在空房間裡衝過頭撞牆，或在終點旁繞圈直到逾時。加上複習後回到 99.6%。
- **牆和隔間的失敗幾乎消失。**在全部拉滿，撞隔間缺口邊緣從佔全部 episode 的 6.4% 降到 0.2%，撞窗戶上下緣從 1.7% 降到 0.1%。每間房的失敗率從 5–7% 降到 0.7–1.0%。
- **剩下的失敗有 2/3 是柱子**（全高柱和吊柱，佔全部 episode 的 3.2%），其次是在吊牆或障礙物之間來回擺盪造成的逾時（0.4%）。
- **代價是變慢**：平均速度從約 2.0 降到 1.6 m/s，仍高於 1 m/s 的要求。

**評估方法修正**：舊的 `eval.py` 收集到固定數量的 episode 就停止，結束得早的 episode（大多是失敗）會被多算，所以成功率被低估。例如第四版的全部拉滿，原本量到 64.7%，修正後是 69.8%。現在每個環境固定只算前 K 個 episode。第四版和第五版的表格都用修正後的方法；第一到三版和拆解測試用的是舊方法，數字可能略為偏低。

注意：Genesis 的無人機模型沒有空氣阻力，馬達反應也是瞬間的，所以速度會比真的 Crazyflie 樂觀。如果要上實機，要先加這兩項（見下方「之後的方向」）。

## 架構

```
train.py / eval.py ── rsl-rl PPO
        │
task/goal_nav_task.py (VecEnv) ── rooms（佈局產生 + GPU 佈局池）/ route / geometry / observations / rewards、control/ctbr.py   ← 純 torch，跟模擬器無關
        │  SimBackend 介面（backends/base.py）
backends/genesis_backend.py   ← 唯一會 import genesis 的檔案
```

- 無人機的物理參數集中在 [config/drone_params.py](config/drone_params.py)，所有後端都共用這一份。
- 碰撞（柱子和牆）和障礙物觀測都用 torch 解析計算，不靠模擬器的接觸偵測，所以換模擬器後判定結果完全一樣。牆是有厚度的線段、柱子是圓，兩者都再乘上一段高度範圍；長度和高度每個 episode 都不同。
- 第一人稱錄影的相機朝向「平滑後的飛行方向」，不是機頭方向：這個 policy 不在乎機頭朝哪（會邊自轉邊平移），固定在機身上的相機大多拍到側面。畫面右上角是小地圖，下方是速度、高度、天花板和所在房間。
- 因為碰撞是解析的，訓練時模擬器裡完全不放障礙物；只有開 viewer 或錄影時才建立用來顯示的柱子和牆。Genesis 建好場景後不能改物體大小，所以每個牆位和柱位都是單位方塊 / 單位圓柱，再用 `set_vverts` 逐 env 改寫頂點，畫成任意長度、高度和角度，而且只更新被畫出來的那個 env。

### 移植到 Isaac Lab

1. 新增 `backends/isaaclab_backend.py`，實作 `SimBackend` 的方法（座標慣例寫在 [backends/base.py](backends/base.py) 開頭的說明裡）。`apply_rotor_thrusts` 可以把每顆馬達的推力換算成力和力矩，再用 `set_external_force_and_torque` 套用。
2. 在 `make_backend()` 註冊 `"isaaclab"`。
3. 執行 `python check_env.py --backend isaaclab`，確認懸停、角速度方向和碰撞判定都和 Genesis 一致。
4. 執行 `python train.py --backend isaaclab`。任務、獎勵、控制器和 PPO 設定都不用改。

## 之後的方向

- **換成深度相機 / 完整 3D**：實作 `SimBackend.get_depth()`（Genesis 用 BatchRenderer，Isaac Lab 用 TiledCamera），把 `obs.mode` 設成 `"depth"`，然後在 `GoalNavTask._compute_obs` 用影像取代柱子和牆那兩段觀測。因為場景全是「2D 形狀 × 高度範圍」的實體，也可以直接在 torch 裡做 ray casting，產生類似光達的距離觀測，不用模擬器渲染。到了這一步，觀測不再依賴「最近 K 個障礙物」的列表，就能加入任意方塊、斜放的障礙、多層樓之間的垂直通道。可以用 rsl-rl 的 distillation，讓這一階段的策略當老師。
- **柱子密集處**：剩下失敗的 2/3 是柱子。可以延長第 5 級的訓練，或讓速度上限在「兩側都有障礙」時再降低一點（目前只看最近的一個）。
- **處理局部極小值**：剩下的逾時大多是在吊牆或兩個障礙物之間來回擺盪。換成有記憶的 policy（rsl-rl 支援 RNN），或讓 policy 也看到房內的下一個路線點（目前只給 critic）。前者比較接近「真正學會找路」。
- **提高速度**：目前平均 1.6 m/s，只要求達標。避障穩定以後，可以逐步把 `rewards.slow_speed` 和 `rewards.max_speed` 往上調、或把 `time` 懲罰加大，再接著訓練，一邊看成功率。
- **上實機**：實作 `domain_rand`（質量、推力、延遲），加入空氣阻力和馬達動態，再用 `runner.export_policy_to_onnx` 匯出策略。
